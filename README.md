# Cash Register Calculator

A simple, mobile-friendly web app for counting a cash register.
Enter how many of each coin and bill are in the till, see the running
total, and (optionally) get a list of items to deposit so the till is
balanced back to a target float (default $200 CAD).

The app is a static site — no backend, no database. Once it's hosted
on GitHub Pages, you can open it on your phone and tap **Add to Home
Screen** to install it like a native app. After the first load it
also works offline.

---

## Features

- **Count by denomination** — one row per CAD coin/bill (5¢, 10¢, 25¢,
  $1, $2, $5, $10, $20, $50, $100). Type a count.
- **Coin rolls** — separate section for full rolls (5¢, 10¢, 25¢, $1,
  $2). Standard Royal Canadian Mint quantities. Rolls count toward
  the till total but are kept as a reserve — the balance algorithm
  never suggests breaking them open.
- **Live total** — shown in a sticky footer that always stays visible.
  Includes both loose items and rolls.
- **Balance to target** — figures out which items to remove so the
  till is left at the target amount, taking the largest items first.
- **Editable settings** — change the target amount and ideal
  composition behind a gear icon. Defaults are sensible enough that
  most users will never open this.
- **Mobile-first** — large tap targets, numeric keyboards, sticky
  footer, sheet-style modals.
- **Installable / offline** — PWA manifest + service worker mean the
  app installs to your home screen and works without internet after
  the first load.

---

## How the balance algorithm works

The "balance" button takes the current counts and computes what to
remove. Four possible outcomes:

1. **Already balanced** — the till is already at the target. Nothing
   to remove.
2. **Removal list** — the till has more than the target. The app
   shows which items to take out (e.g. *"Remove 2× $20, 1× $10"*).
3. **Shortfall** — the till has less than the target. The app says
   how much you're short and which loose denominations are below ideal.
4. **Unreachable** (rare) — the till is over the target, but the
   items present don't allow an exact match (e.g. you have $3 over
   but only $5 bills). The app says so explicitly rather than
   offering a wrong answer.

The algorithm is a **single-pass, largest-first greedy** over the
loose bills and coins. Coin rolls count toward the till's total but
are *never* suggested for removal — they stay as a reserve.

If the till is over the target purely because of rolls (e.g. you
have $250 in rolls and zero loose, target $200), the algorithm
returns "unreachable" rather than suggesting you break a roll. You
have to break one yourself (or adjust the target).

This is implemented in `computeBalance()` in `app.js`.

## File layout

```
cash_register_calculator/
├── index.html               Markup and UI shell
├── style.css                All styles, mobile-first
├── app.js                   State, totals, balance algorithm, modal logic
├── manifest.webmanifest     PWA metadata (name, icons, standalone display)
├── sw.js                    Service worker (offline cache)
├── icons/
│   ├── icon-192.png         Home-screen icon (Android, iOS)
│   └── icon-512.png         Larger icon (splash, maskable)
├── generate_icons.py        Helper script that generated the icons
│                            (kept for re-running if you change the
│                             colour or design — not required at runtime)
└── README.md                This file
```

### What each file does

- **`index.html`** — Bare markup. The denomination rows are *not*
  hardcoded here; they're built by `app.js` from the `DENOMINATIONS`
  list. The footer holds the running total + the "Balance" button.
  Two hidden modals (balance result and settings) live at the bottom
  of the body.
- **`style.css`** — One stylesheet, written mobile-first. Contains
  `safe-area-inset` padding for iPhone notches/home-indicators, large
  tap targets (≥ 44 px), and a small media query for tablet/desktop
  width. No build step, no preprocessor.
- **`app.js`** — All app behavior, in 8 numbered sections. Reads
  top-to-bottom: constants → state → helpers → render → balance
  algorithm → modals → wiring. All money is stored as integer cents
  internally to avoid floating-point bugs. Two top-level constants
  drive the UI: `DENOMINATIONS` (loose bills/coins) and `COIN_ROLLS`
  (full rolls).
- **`manifest.webmanifest`** — Tells the browser this site is
  installable as an app, what icons to use, and what colors / display
  mode to apply when launched from the home screen.
- **`sw.js`** — Pre-caches the app shell on first install, then serves
  files from cache so the app works without a network. Bump
  `CACHE_VERSION` inside the file when you change any of the cached
  files so the new version replaces the old.
- **`icons/`** — PNG icons referenced by the manifest. Generated by
  `generate_icons.py`; you can regenerate them by editing the script
  and re-running it.

## Running locally

The app is a plain static site. The simplest way to try it:

```sh
# from the project folder, in any terminal
python -m http.server 8000
# or
npx serve
```

Then open `http://localhost:8000` in your browser.

> ⚠️ Service workers don't run when you open `index.html` directly
> via `file://` in the browser. Use a local server (or just deploy)
> for the offline / PWA features to work. Counting and balancing
> still work fine in `file://` mode — you just don't get the
> install/offline experience.

## Hosting on GitHub Pages

1. Create a new GitHub repo (suggested name: `cash-register-calculator`).
2. Push this folder's contents to the repo's `main` branch.
3. In the repo on github.com → **Settings** → **Pages**.
4. Under **Source**, choose `Deploy from a branch`, pick `main` and
   `/ (root)`, then click **Save**.
5. After a minute or two, GitHub publishes the site at
   `https://<your-username>.github.io/cash-register-calculator/`.

### Installing on your phone

1. Open the URL above in **Chrome** (Android) or **Safari** (iOS).
2. Tap the share / menu button → **Add to Home Screen**.
3. The app icon appears on your home screen and launches in
   standalone mode (no browser UI).

## Tweaking the defaults

Open the gear icon in the running app to change the target amount and
the ideal composition. If you want to change the *default* values
(what the "Reset to defaults" button restores), edit the `DEFAULTS`
object near the top of `app.js`.

If you want to add or remove a denomination, edit the `DENOMINATIONS`
list — the UI rebuilds itself from that list, so the rest of the app
adapts automatically. (Just remember to update `DEFAULTS.ideal` so the
composition still sums to the target.) The same goes for `COIN_ROLLS`
if you ever change the standard roll quantities.
